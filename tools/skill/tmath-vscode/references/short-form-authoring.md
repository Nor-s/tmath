# Authoring short-form code stories

Read this only when the user explicitly requests short-form/숏폼/Shorts/Reels-style code visualization or an intentionally high-energy code-review series. Use [tmath-skills](../../tmath-skills/SKILL.md), its [algorithm-and-code profile](../../tmath-skills/references/profiles/algorithm-and-code.md), [animation-authoring.md](animation-authoring.md), and [short-form-code-stories.md](short-form-code-stories.md). Portrait geometry or a request to be engaging does not activate this mode.

## Adapt short-form to an editor

The VS Code viewer is silent-first and already supplies transport, title, description, series navigation, and source access. Do not recreate social controls, phone chrome, subtitles, autoplay feed, engagement metrics, sound dependency, or platform branding.

One episode resolves one verified claim. Its initial frame states or shows the real question; each beat exposes a source-backed input, condition, state transition, or diff consequence; the final frame retains the answer and necessary evidence as a complete still. Default to `loop=false`. Enable looping only when explicitly requested or when the mechanism has a truthful causal return, and then verify the seam.

Use vertical space only when the evidence remains legible through FIT and hover reduction. Otherwise choose another ratio. Keep authored content inside a conservative safe region and keep viewer UI outside Canvas. If one claim cannot remain readable, lengthen the episode, remove a subordinate beat, or split the manifest series before accelerating motion or shrinking text.

## Keep energy evidential

Interpret energy as frequent meaningful payoff, not constant velocity. Preserve stable context, use one dominant change per beat, and hold the resolved state long enough to read. A clean framing or palette change may mark a genuine semantic surprise; repeated cuts, flashing, shake, fake urgency, clickbait, or empty cliffhangers obscure evidence.

Use concise Theme-aware text and verified code fragments. Put revision details, caveats, alternate branches, and benchmark conditions in the manifest description. Preserve one terminology and causal order across Canvas, description, `links`, Inspector, and series titles. Link only product source; never expose the animation Lua as evidence.

## Series and verification

Each episode must make one verified claim, name its source revision and representative scenario, and stand alone from a hover or direct open. Put its direct Lua at `.vscode/tmath/<series>/animations/<scene>.lua`; make manifest `links` execution-ordered. Reuse visual grammar, theme, and aspect ratio across the series, but let each final still retain the resolved answer and evidence. Let the existing Previous, Series, and Next controls navigate; never draw episode navigation inside Canvas. Split an episode before shrinking text or accelerating meaningful motion. Automatic transitions remain viewer policy.

Inspect the whole episode, opening, exact final frame, narrow and Wide FIT, Canvas Full Screen, and generated hover at normal speed. Confirm every attention-grabbing transition maps to evidence, the promise is resolved, source navigation stays outside Canvas, and the same Preview/manifest/playback/export paths work unchanged.
