# Authoring editor cheatsheets

Read this after the [tmath-skills cheatsheet profile](../../tmath-skills/references/profiles/cheatsheet.md) and [animation-authoring.md](animation-authoring.md). It adapts an evidence-dense plate to code-side viewing; it does not define a new viewer mode or visual style.

## Select this format from evidence

Use an editor cheatsheet when several verified source regions, runtime states, calls, or invariants should remain simultaneously inspectable. Prefer an ordinary animation when one temporal mechanism dominates; use the relevant diagram method under [tmath-skills](../../tmath-skills/SKILL.md) when relationships or topology dominate. Portrait is an option, not a trigger. Follow an explicit user format.

The viewer uniformly scales one fixed Canvas and never scrolls inside it. Choose a bounded aspect ratio that remains legible in a narrow editor group and hover output. Split dense material into independently useful manifest-series episodes before increasing height or shrinking typography. Use a dual-plate Wide composition only when two simultaneous evidence regions genuinely require it.

## Build a self-contained plate

Keep the complete information structure visible at the initial frame:

- one compact subject heading;
- short verified product-code anchors;
- one dominant mechanism plus only the supporting states or invariants needed to explain it;
- natural section titles and concise interpretation where the visual alone is ambiguous.

This is a content model, not a module count. Use the selected Theme and `adaptive_vscode` host behavior from [animation-authoring.md](animation-authoring.md); do not add editor-themed cards, badges, magazine furniture, or a second UI system.

Source paths, file names, directories, and line locations are navigation metadata. Keep them in the manifest and Inspector, never on Canvas or in explanatory prose. Show only the decisive condition, call, mutation, return, or signature—not a whole function or decorative listing. The visible fragment may be a strict subset of the broader manifest range.

## Make source order the spine

Trace the representative runtime path first. Preserve one order across runtime step, manifest link, Inspector entry, visible anchor, titled mechanism, and explanation. When sections use stable identifiers, repeat the exact identifier in the corresponding `links[].label`; do not invent an identifier only in the manifest. For branches, name the demonstrated condition. For concurrent work, order by causal handoff and show overlap rather than inventing serial execution.

Each Related Source range should contain the coherent local input or governing branch, operation, and immediate result or handoff. Split noncontiguous evidence into separate ordered links. Never use the tmath animation implementation, helper Lua, generated GIF, or authoring calls as evidence.

## Preserve plate behavior

Keep anchors, titles, stable context, and each mechanism's summary pose visible without playback. Animate evidence locally rather than revealing the page as slides. Editor plates default to `loop=true` and must restore their complete readable pose at the seam; optional playback ranges need stable independent entry states. Do not require camera motion or playback order to discover the structure.

Verify the complete loop and generated hover at every delivery mode listed in [animation-authoring.md](animation-authoring.md). If narrow FIT fails, reduce copy, reflow, or split the series before shrinking text.
